# 师门助手紧凑布局设计

## 目标

把师门助手改造成桌面优先的高密度操作台，让用户无需逐行浏览即可同时看见并操作多个账号，并让常用商会店铺编号在一屏内完成速查。

本次只调整信息架构、组件展示形态和视觉密度，不修改账号计时、推荐算法、提醒规则、数据模型与本地持久化行为。

## 页面结构

- 页面顶部压缩为单行或紧凑双行标题栏，保留系统通知和重置今日进度操作，弱化介绍文字。
- 今日统计与高价值提醒压缩高度。没有等待或到期账号时，提醒区域使用单行空状态；存在提醒时，账号与操作以紧凑条目展示。
- 账号工作台作为页面主要视觉区域，桌面端使用自适应多列网格，窄屏逐步降为双列和单列。
- 商会速查位于账号区之后，四个分类同页展示，搜索与新增能力保持可见。

## 账号工作台

账号不再呈现为纵向大卡片列表，而是平铺为紧凑操作卡：

- 卡片顶部展示账号名、状态和推荐标记。
- 有效耗时使用等宽数字并保持足够醒目，但缩小标签、间距与整体字号。
- 开始、继续、暂停、高价值、完成、撤销完成直接显示在卡片内，用户无需展开或进入详情。
- 编辑和删除降为次级操作，避免与每日高频动作争夺注意力。
- 备注仅在存在时显示，并限制占用空间，不能撑高整组卡片。
- 保留拖拽排序和键盘上下移动能力。

推荐账号沿用现有领域算法，不自动启动。推荐卡使用明显但克制的暖色底、强化描边和星标标签，并在视觉层级上明显高于普通账号；不能只依靠颜色表达推荐状态。

## 店铺速查

三药、家具、烹饪采用编号胶囊墙：

- 默认只显示店铺编号，不显示店名、商品和备注。
- 编号胶囊本身是主要编辑入口，点击后打开现有编辑表单。
- 胶囊保留拖拽排序，并提供可访问名称说明对应分类和店铺信息。
- 分类标题旁保留新增入口与数量统计。
- 搜索仍匹配编号、名称、商品和备注；命中后仍只展示编号胶囊。
- 删除不放在胶囊墙表面，进入编辑表单或沿用不增加视觉噪音的管理入口；若现有表单不支持删除，则保留胶囊旁极简删除控件。

召唤兽分类继续展示店铺编号、店名、商品和备注，并保留编辑、删除和排序能力，但缩小内边距、字号和按钮尺寸，使其与新页面密度一致。

## 响应式与可访问性

- 桌面端优先保证账号与编号的同屏数量；中等宽度减少列数；移动端使用单列账号卡，并允许胶囊自然换行。
- 所有每日操作使用原生按钮，保留清晰的键盘焦点和可访问名称。
- 推荐、计时、等待和完成状态同时使用文字或图标，不单靠颜色区分。
- 可点击区域不因视觉压缩而小于合理触控尺寸；桌面端紧凑按钮与移动端触控尺寸分别处理。
- 过长账号名、备注和店铺编号必须换行或截断，不能撑破网格。

## 组件边界

- `SectMissionView.vue` 只负责页面编排和提醒区密度。
- `AccountBoard.vue` 负责统计与账号网格，不接管账号业务动作。
- `AccountCard.vue` 负责紧凑账号卡及直接操作。
- `ShopPanel.vue` 负责商会标题、搜索和分类编排。
- `ShopCategorySection.vue` 根据分类选择胶囊墙或详细列表。
- `ShopCard.vue` 保留召唤兽详细卡展示。
- 新增轻量编号胶囊组件时，只承担单个店铺的展示、排序、编辑和必要的删除入口，不访问 store。

## 验收标准

- 桌面端账号以多列平铺方式呈现，一眼可见多个账号及其主要操作。
- 推荐账号拥有显著且不依赖单一颜色的视觉标识。
- 三药、家具、烹饪默认仅展示店铺编号胶囊。
- 召唤兽仍展示完整店铺资料。
- 账号计时、推荐、等待、完成、编辑、删除和排序行为保持不变。
- 店铺搜索、新增、编辑、删除和排序行为保持可用。
- 页面在桌面、平板和手机宽度下无横向溢出。
- 构建、类型检查和 lint 通过，浏览器控制台无新增错误或警告。

## 非目标

- 不修改推荐账号算法。
- 不修改五分钟提醒逻辑。
- 不修改数据结构或迁移本地数据。
- 不新增账号筛选、分组、批量操作或自动启动。
- 不新增单元测试文件。
