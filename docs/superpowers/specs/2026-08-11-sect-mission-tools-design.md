# 梦幻西游师门工具站设计

## 1. 目标

构建一个面向个人多开玩家的纯静态梦幻西游工具站。首页负责导航到各个工具，第一期提供“师门助手”：用户可以并行管理多个账号的师门有效耗时，在遇到高价值物品时为对应账号暂停计时并启动五分钟取消提醒，同时在同一页面快速检索和维护商会店铺。

成功标准：

- 用户能在一个页面看清所有账号的当日状态、有效耗时、高价值等待和推荐顺序。
- 多个账号可以同时计时，任一账号的暂停、等待或完成都不影响其他账号。
- 刷新或关闭页面后，账号、计时状态、倒计时、店铺和排序仍能恢复。
- 商会店铺按三药、家具、召唤兽、烹饪四类同页展示，并支持搜索、增删改查和拖拽排序。
- 跨过本地自然日后，只重置师门当日进度，不删除账号资料、店铺资料和排序。
- 页面在桌面端适合长时间使用，并能在较窄窗口中保持可操作。

## 2. 范围

### 2.1 本期包含

- 首页工具导航。
- 师门助手页面。
- 账号新增、编辑、删除和拖拽排序。
- 账号独立开始、暂停、继续、高价值等待、完成和撤销完成。
- 有效耗时实时显示。
- 推荐下一个账号。
- 多个独立五分钟倒计时和到期提醒。
- 商会店铺同页分类展示、搜索、新增、编辑、删除和拖拽排序。
- 浏览器本地持久化、数据版本和每日自动重置。
- 窄窗口响应式布局。

### 2.2 本期不包含

- 登录、后端服务和多设备同步。
- 师门环数记录及历史日报。
- 自动操作游戏、自动切换账号或自动开始计时。
- 除首页扩展入口以外的其他梦幻西游工具。
- 单元测试文件；按用户要求使用类型检查、生产构建和浏览器实测验收。

## 3. 技术选型

- 构建工具：Vite。
- 应用框架：Vue 3 + TypeScript，统一使用 Composition API 和 `<script setup>`。
- 路由：Vue Router Hash 模式，首页为 `/#/`，师门助手为 `/#/sect-mission`，确保任意静态托管环境直接刷新都不会依赖服务端回退规则。
- 状态管理：Pinia。
- 拖拽排序：`vue-draggable-plus`。
- 图标：`lucide-vue-next`。
- 样式：原生 CSS，自定义设计变量和组件样式，不引入通用 UI 框架。
- 持久化：浏览器 `localStorage`。
- 通知：页面提醒、Web Audio 提示音、标签页标题变化；用户授权后追加 Web Notification。

选择轻量定制方案，是为了避免通用后台组件库带来的视觉同质化，并让未来新增工具时仍能复用路由、导航、状态和主题基础设施。

## 4. 信息架构与视觉

采用用户确认的“A：左侧导航工作台”方案：

- 桌面端使用固定左侧导航，包含首页、师门助手和更多工具占位。
- 首页使用欢迎区和工具卡片，清楚区分可用工具与后续扩展位。
- 师门页顶部展示今日概况和推荐账号。
- 账号队列是主工作区，以可拖拽卡片展示账号状态、有效耗时和操作。
- 高价值倒计时集中展示，避免提醒被藏进账号卡片。
- 商会速查位于同页侧栏，搜索框常驻，四类店铺分组展示。
- 较窄窗口中，侧栏导航折叠为顶部导航，商会区域排列到账号区域下方。

视觉使用低饱和薄荷绿、暖白背景和深绿文字。高亮只用于推荐、进行中和提醒状态。状态必须同时使用文字、图标和颜色表达，不能只依赖颜色。

## 5. 数据模型

### 5.1 本地根数据

```ts
interface PersistedState {
  version: number
  activeDate: string
  accounts: Account[]
  shops: Shop[]
}
```

`activeDate` 使用浏览器本地日期的 `YYYY-MM-DD`。应用启动和日期变化时比较该字段，决定是否执行每日重置。

### 5.2 账号

```ts
type AccountStatus = 'idle' | 'running' | 'paused' | 'waiting' | 'ready' | 'completed'

interface Account {
  id: string
  name: string
  note: string
  order: number
  status: AccountStatus
  accumulatedMs: number
  startedAt: number | null
  waitingUntil: number | null
}
```

- `accumulatedMs` 保存已经结算的有效耗时。
- `startedAt` 只在 `running` 状态存在。
- `waitingUntil` 只在 `waiting` 状态存在。
- 页面显示的有效耗时为 `accumulatedMs + (now - startedAt)`，不把暂停或等待时间计入。
- 编辑账号资料不改变当日进度；删除账号时一并删除其当日状态。

### 5.3 商会店铺

```ts
type ShopCategory = 'medicine' | 'furniture' | 'summon' | 'cooking'

interface Shop {
  id: string
  category: ShopCategory
  number: string
  name: string
  items: string[]
  note: string
  order: number
}
```

店铺在分类内排序。搜索同时匹配编号、名称、商品和备注，结果仍按四个分类同页分组展示。

## 6. 状态规则

### 6.1 账号操作

- `idle`：可开始。
- `running`：可暂停、进入高价值等待或完成。
- `paused`：可继续或完成。
- `waiting`：显示剩余五分钟，不允许提前恢复有效计时。
- `ready`：等待已经到期，可由用户手动继续或完成。
- `completed`：固定最终有效耗时，可撤销为暂停状态，防止误点后丢失进度。

开始、暂停、继续、等待和完成均只影响目标账号。系统不限制同时处于 `running` 状态的账号数量，也不会根据推荐结果自动修改账号状态。

### 6.2 高价值等待

用户在计时中账号上点击“高价值”时：

1. 结算当前有效耗时。
2. 将账号切换为 `waiting`。
3. 保存当前时间后五分钟的绝对截止时间。
4. 到期后切换为 `ready`，播放提示音、显示页面提醒、改变标签页标题。
5. 如果用户已授予浏览器通知权限，追加一条系统通知。

使用绝对截止时间而非每秒累减，避免标签页后台节流或刷新造成倒计时漂移。

### 6.3 推荐算法

候选账号排除 `completed` 和 `waiting`。其余账号按实时有效耗时升序排列；耗时相同则按用户拖拽顺序升序排列。第一名只被高亮为推荐账号，必须由用户手动开始或继续。

### 6.4 每日重置

当本地日期与 `activeDate` 不一致时：

- 所有账号恢复为 `idle`。
- 清空有效耗时、开始时间和等待截止时间。
- 保留账号名称、备注和排序。
- 保留全部店铺和排序。
- 更新 `activeDate`。

手动重置执行同样操作，必须经过二次确认。

## 7. 模块边界

- `layouts/`：站点导航和整体页面框架，不包含业务状态。
- `views/`：首页与师门页面，只负责组装功能模块。
- `stores/`：账号、计时、每日重置、推荐和商会数据的唯一状态来源。
- `components/accounts/`：账号列表、账号卡片、账号表单和提醒列表。
- `components/shops/`：店铺搜索、分类分组、店铺卡片和店铺表单。
- `components/common/`：弹窗、确认框、提示消息和通用空状态。
- `composables/`：当前时间刷新、通知和本地存储边界。
- `types/`：持久化数据和领域类型。
- `styles/`：设计变量、基础样式和响应式规则。

组件不得直接读写 `localStorage`。所有持久化和迁移由状态层统一处理，避免页面组件与存储格式绑死。

## 8. 数据流与持久化

1. 应用启动时加载本地数据。
2. 校验根结构和版本；可识别的旧版本执行迁移。
3. 数据无法解析时，将原始字符串复制到带时间戳的备份键，恢复为空数据并向用户显示警告。
4. 检查本地日期并执行必要的每日重置。
5. 用户操作调用 Pinia action 修改领域状态。
6. 状态变化后统一序列化写入 `localStorage`。
7. 页面每秒更新一次显示时钟，但不每秒写入持久化数据。
8. 页面隐藏、关闭或刷新前结算运行中账号并立即持久化。

第一期持久化键使用命名空间前缀，避免与同域后续工具冲突。

## 9. 表单与错误处理

- 账号名称必填并去除首尾空白。
- 店铺分类、编号和名称必填；商品允许使用顿号、逗号或换行输入，保存时统一为去空白、去空值、去重后的字符串数组。
- 删除账号、删除店铺和重置当天数据均需二次确认。
- 本地存储写入失败时提示用户，当前内存状态仍保留，但不得假装已经保存。
- 通知权限被拒绝时不报错，继续使用页面提醒和声音。
- 拖拽结果在操作结束后一次性保存，不在拖动过程中频繁写盘。

## 10. 代码规范

- 所有业务方法必须写清晰的中文注释，说明行为、边界或为什么这样处理。
- 使用严格 TypeScript，避免 `any`。
- 组件保持单一职责，页面只做组合，不塞入大段领域逻辑。
- 不为兼容测试写冗余分支，不创建单元测试文件。
- 命名使用英文，界面文案和业务注释使用中文。
- Git 提交说明使用中文描述。

## 11. 命令与验证

计划提供以下命令：

```bash
npm run dev
npm run type-check
npm run lint
npm run build
```

验收步骤：

1. 运行类型检查、代码检查和生产构建，全部以退出码 0 结束。
2. 在真实浏览器新增多个账号，同时开始计时，确认互不干扰。
3. 对账号执行暂停、高价值等待、完成和撤销完成，确认有效耗时只统计运行区间。
4. 同时启动多个高价值倒计时，确认分别到期、提醒和恢复。
5. 刷新页面，确认运行中计时、等待截止时间、排序和店铺数据恢复。
6. 调整账号耗时和状态，确认推荐算法遵守排除规则与最少耗时规则。
7. 新增、编辑、删除、搜索和拖拽四类店铺，确认分类内排序持久化。
8. 模拟本地跨日数据，确认只重置师门当日进度。
9. 检查桌面和窄窗口布局、键盘焦点、按钮标签和颜色对比度。

- 维护本地数据的向后兼容和损坏备份。

### 需要先询问

- 自动开始推荐账号或限制并行计时账号数量。
